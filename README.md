## 1. 改造背景与定位

v1 是一个**能演示、能交互**的助农电商前端与最小后端（**小组 2 人于 2026 年春季共同完成**的计算机设计大赛作品）。
问题在于：**它能跑，但没人验证过它算得对**。

我是 v1 的作者之一。2026 年秋，我把它当作自己的质量建设对象，接入真实接口测试后动手改造：

- **不改产品形态**——页面、交互、视觉与 v1 完全一致，改造集中在**后端正确性、数据一致性与工程规范**；
- **每一条改动都有一条可执行断言**——断言写在独立的测试工程里，不是"改完觉得对了"；
- **改造的可信度靠对照实验**——同一套测试 harness 同时打**原版（Node/Express）**和
  **重写版（Python/FastAPI）**，用"违反不变量的条数"做量化对照。

## 2. 改造中实测定位的缺陷

以下 4 个问题都是在**真实启动服务后复现**的，不是静态阅读推测出来的。

| # | 缺陷 | 复现方式 | 实际结果 | 位置 |
|---|---|---|---|---|
| 1 | `quantity` 无正整数校验，传负数令库存虚增 | `POST /api/orders {"quantity": -5}` | 库存 999 → **1004** | `backend/server.js:329 / 377` |
| 2 | `total_price` 返回单价而非「单价 × 数量」；`price` 字段是 TEXT | `{"quantity": 2}` | `total_price = "¥1288"`（实为单价） | `backend/server.js:387` |
| 3 | 库存扣减是「读-判-写」且未 await、无事务 → 并发超卖 | 12 并发抢 5 件库存 | **12 单全成功、stock = -7** | `backend/server.js:329 / 377` |
| 4 | 商品列表页仍读 `data.js` 静态常量，未接后端 | 后端改价后刷新列表页 | 列表页价格不变（前后端两个价） | `products.html:416` |

复现脚本与数据库前后快照见 [`yijiyixian-qa`](https://github.com/Yunffu/yijiyixian-qa)。

> 附带发现：该系统**没有任何角色模型**（无商家 / 无管理员），这直接决定了后面权限矩阵的形状。

## 3. 质量目标：5 条业务不变量

改造的断言主轴不是 HTTP 状态码，而是 5 条**业务不变量**——每条都能同时表达为
「响应字段断言」与「数据库终态断言」：

| # | 不变量 | 含义 |
|---|---|---|
| 1 | **库存守恒** | 初始库存 = 期末库存 + 所有有效订单数量之和（取消的订单要回滚） |
| 2 | **金额守恒** | `total_price = 单价 × 数量`，且取自**下单时价格快照** |
| 3 | **库存非负** | 任何路径下 `stock >= 0`，并发下不超卖 |
| 4 | **订单归属** | 只能读取 / 取消自己的订单（横向越权走不通） |
| 5 | **状态机合法迁移** | `pending → cancelled` 合法；`cancelled → cancelled` 非法 |

## 4. 改造路线

### 阶段 A · 数据与接口正确性
- [ ] `quantity` 正整数校验（非法值返回 400）
- [ ] `price` 改为数值列；`total_price = 单价 × 数量`；订单落**下单时价格快照**
- [ ] 原子扣减：`UPDATE products SET stock = stock - ? WHERE id = ? AND stock >= ?` + 校验影响行数
- [ ] 下单 / 取消订单纳入事务，取消时做金额与库存冲销

### 阶段 B · 前端一致性
- [ ] `products.html` 列表页接入 `ProductAPI.list`，去掉 `mockProducts`
- [ ] `js/api.js` 的 `API_BASE` 改为同源相对路径 `/api`，消除硬编码域名

### 阶段 C · 可测试性与工程化
- [ ] 统一异常码表与错误响应结构
- [ ] 参数校验下沉到统一的校验层
- [ ] 接口日志（含 trace_id）便于定位
- [ ] 数据库索引补充
- [ ] GitHub Actions CI

## 5. 双 SUT 对照实验

同一套测试 harness 参数化打到两套实现，用来回答「**改造后的语义等价性**」这个问题：

```
              ┌─────────────────────────┐
              │  harness（断言 + 夹具）   │
              │  5 条业务不变量 + 用例矩阵 │
              └────────┬────────┬───────┘
                       │        │
              sut=node│        │sut=python
                       ▼        ▼
              Express 原版    FastAPI 重写版
              （v1 行为）      （D7–D8 重写）
```

- 重写版重写 **8 个核心接口 + 4 张表**（含 bcrypt + JWT），目的是让"接口契约"从
  一段自然语言变成**可执行的 schema**；
- 对照指标：**违反不变量的用例条数**（原版违反 N 条 / 重写版 0 条）、回归耗时、重复运行稳定性。

用例矩阵与断言实现在 [`yijiyixian-qa`](https://github.com/Yunffu/yijiyixian-qa)。

## 6. 技术栈

| 层 | 技术 |
|---|---|
| 前端 | 原生 HTML / CSS / JavaScript（无框架）、GSAP 动效、D3 v7、原生 `fetch` |
| 后端 | Node.js + Express 4、SQLite（`sqlite3`）、JWT（`jsonwebtoken`）、bcrypt（`bcryptjs`）、CORS |
| 端口 | 后端 `3001`，前端由 Express 静态托管（同源） |
